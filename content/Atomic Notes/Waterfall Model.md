### Waterfall model
#### Principals
- Linear sequence of development cycle
- Requirement defined at start
- Each stage serves as input to the next stage
- Each stage completed and signed off before next stage
- Sometimes to continue work on a stage, previous stage will require more work to be done for it
#### Benefits
1. Simple to understand as the stages are clearly defined
2. Each stage has fixed outcomes, thus **easier to manage**
3. Stages are processed and completed one at a time
4. Works well for small projects as requirements can be easily defined
5. **Detailed documentation**
6. **Smooth development process** as project is planned thoroughly 
7. **Less time period required**
#### Drawbacks
1. No demo software made until end of the lifecycle
2. Not good for complicated projects
3. Not good for object oriented projects
4. Poor model for long/on going projects
5. Not flexible for new requirements
6. Difficult to measure progress
